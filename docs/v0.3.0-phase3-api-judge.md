# Prompt Jury v0.3.0 Phase 3 API Judge

Status: Complete  
Scope: OpenAI-compatible API provider and hardened API client

## Implementation

`OpenAICompatibleJudgeProvider` wraps the existing v0.2.8 API Judge behind the Phase 2 `JudgeProvider` contract. It accepts already-blinded `JudgeInput`, converts candidates into the existing prompt format, applies the run-specific evaluation criteria, and returns the canonical rich `JudgeResult`.

The Provider is available only when:

- the Base URL is a valid HTTP or HTTPS URL;
- API Key and Model are present;
- request timeout is greater than zero.

Synthesis-only mode is rejected by this evaluation Provider because synthesis returns text rather than `JudgeResult`. The existing synthesis client remains unchanged until its later engine/UI integration.

## API compatibility

- API root URLs are expanded with `/chat/completions`.
- Full Chat Completions URLs are preserved.
- Query parameters such as Azure `api-version` are preserved.
- Standard OpenAI-compatible services use `Authorization: Bearer`.
- Azure deployment URLs use the `api-key` header.
- Normal JSON and SSE response envelopes remain supported.
- Every API call is a new stateless request with no conversation reuse.

## Reliability and security

- Requests use `AbortController` with a 180-second default timeout.
- Authentication and rate-limit failures are not retried.
- Transient network, timeout, HTTP, response-envelope, and Judge JSON failures retain the existing single retry where appropriate.
- Authentication, rate-limit, timeout, network, HTTP, and invalid-response failures use typed `JudgeApiError` codes.
- HTTP response details are bounded to 300 characters, flattened to one line, and stripped of the configured API Key.
- Authorization values never enter request bodies, Judge results, logs, or exports.
- Judge Core removes candidate provider and model identity before the API Provider is invoked.
